# AI 生图/生视频工具站 — 网页设计文档

版本：v0.1 draft ｜ 日期：2026-08-24 ｜ 配套文档：[需求文档.md](需求文档.md) · [API接口文档.md](API接口文档.md)

---

## 1. 设计理念

**方向：暗色科技感 + 渐变光晕 + 玻璃拟态（Glassmorphism）**，对齐 Midjourney / Runway / Leonardo.ai 等主流 AI 创作工具的产品气质——专业、沉浸、突出生成内容本身。

设计原则：
1. **内容为王**：UI 退居幕后，生成的图片/视频永远是视觉焦点；面板、控件用低对比度深色 + 细边框，避免和作品抢视觉。
2. **一步到位的创作流**：从输入提示词到看到结果，中间不出现多余的跳转/弹窗打断心流；参数常驻侧边、结果即时呈现。
3. **可信赖的透明感**：涉及 Key、费用、数据存储位置的地方，用清晰文案 + 图标提示，而不是藏起来，呼应"BYOK + 本地存储"的产品诚意。
4. **克制的科技感**：渐变/光晕/发光边框适度使用在关键行动点（生成按钮、进行中状态），不做满屏动效，保持专业而非炫技。

## 2. 视觉系统

### 2.1 色彩

暗色为默认主题（更符合创作类工具的沉浸感），预留浅色主题作为二期。

| Token | 值 | 用途 |
|---|---|---|
| `--bg-base` | `#0B0C10` | 页面底色 |
| `--bg-surface` | `#131418` | 卡片/面板背景 |
| `--bg-surface-2` | `#1B1D24` | 输入框/次级面板 |
| `--bg-glass` | `rgba(255,255,255,0.04)` + `backdrop-blur` | 玻璃拟态浮层 |
| `--border-subtle` | `rgba(255,255,255,0.08)` | 常规描边 |
| `--border-strong` | `rgba(255,255,255,0.16)` | 强调描边/hover |
| `--text-primary` | `#F5F6F8` | 主文字 |
| `--text-secondary` | `#9AA0AC` | 次级文字 |
| `--text-muted` | `#5C6270` | 弱提示/禁用文字 |
| `--accent-violet` | `#7C5CFF` | 品牌主色（按钮、激活态、进度） |
| `--accent-cyan` | `#42E8E0` | 品牌副色（渐变搭配、视频模块强调） |
| `--accent-gradient` | `linear-gradient(135deg, #7C5CFF 0%, #42E8E0 100%)` | 主行动按钮、Logo、生成中光效 |
| `--success` | `#3DD68C` | 完成/成功 |
| `--warning` | `#F5B34C` | 参数超限/费用提示 |
| `--danger` | `#FF5C7A` | 错误/失败 |

深浅主题的语义 token（`success`/`warning`/`danger`/`accent`）保持不变，仅 `bg-*` / `text-*` 系列在浅色主题下反转，二期实现时按此表补一份浅色映射即可。

### 2.2 字体

- 西文/数字：`Inter`（UI 常用几何无衬线，专业感强），系统兜底 `-apple-system, "Segoe UI", sans-serif`。
- 中文：`"HarmonyOS Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif`。
- 等宽（用于展示 API 请求预览/JSON 面板等开发者向内容）：`"JetBrains Mono", ui-monospace, monospace`。

字号阶梯（rem，基准 16px）：`display 2.5 / h1 2 / h2 1.5 / h3 1.25 / body 1 / small 0.875 / caption 0.75`，行高统一 1.5（标题 1.25）。

### 2.3 间距与圆角

- 间距刻度：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64`px（4px 基准网格）。
- 圆角：卡片 `16px`，按钮/输入框 `10px`，缩略图/头像 `8px`，浮层大面板 `20px`。
- 阴影：`0 8px 24px rgba(0,0,0,0.35)` 用于悬浮卡片；关键 CTA 按钮叠加 `0 0 24px rgba(124,92,255,0.35)` 光晕。

### 2.4 组件规范（要点）

- **主行动按钮（生成/优化）**：渐变填充 `--accent-gradient`，圆角 10px，hover 轻微上浮 + 光晕增强，loading 态显示环形进度替换文字并禁用点击。
- **次级按钮**：透明背景 + `border-subtle`，hover 变 `border-strong`。
- **输入框/文本域**：`bg-surface-2` + `border-subtle`，focus 态描边变 `accent-violet` 并加 2px 外发光。
- **Tab 切换（文生图/图生图/多图合成/视频生成）**：胶囊型分段控件，激活项用渐变底色 + 白色文字，非激活为透明+次级文字。
- **卡片（画廊/任务）**：`bg-surface` + `border-subtle`，hover 时上浮 2px、边框转亮，右上角悬浮显示快捷操作（下载/收藏/复用参数/删除）。
- **Toast 通知**：右下角堆叠，成功/警告/错误用左侧色条 + 对应语义色图标。
- **进度指示**：文本流式=打字机光标；图片生成=骨架屏 + 呼吸光效；视频任务=线性进度条 + 状态徽章（排队中/生成中/已完成/失败，对应中性/violet/success/danger 配色）。
- **Modal/抽屉**：设置中心、大图预览均用玻璃拟态浮层，背景做 `backdrop-blur(20px)` + 半透明遮罩，避免生硬的纯黑蒙层。

## 3. 信息架构与整体布局

### 3.1 页面级导航

```
┌───────────────────────────────────────────────────────────┐
│  顶部导航条：Logo | 创作工作台  历史画廊  任务中心 | 设置 头像态Key状态点 │
├───────────────────────────────────────────────────────────┤
│                                                             │
│                     （各页面内容区）                          │
│                                                             │
└───────────────────────────────────────────────────────────┘
```

顶部导航条右侧常驻一个 **Key 状态指示点**（绿=已配置有效 / 灰=未配置 / 红=校验失败），点击直达设置中心——这是"无账号体系"下最重要的状态可见性设计。

### 3.2 创作工作台（核心页）三栏布局（桌面端）

```
┌───────────┬─────────────────────────────┬───────────────┐
│  左栏      │        中栏（主创作区）         │   右栏         │
│ 功能切换   │  提示词输入框 + [优化✨]按钮      │  历史/结果流    │
│ 文生图     │  ─────────────────────      │  （最近生成的    │
│ 图生图     │  参数面板：尺寸/比例/时长…       │   缩略图网格，  │
│ 多图合成   │  上传区（图生图/多图/视频用）      │   点击可复用/  │
│ 视频生成   │  ─────────────────────      │   放大/下载）  │
│           │  [ 生成 ] 主按钮（渐变+光晕）      │               │
│           │  ─────────────────────      │               │
│           │  结果预览区（大图/视频播放器）      │               │
└───────────┴─────────────────────────────┴───────────────┘
```

- 左栏：图标+文字的竖直功能导航，宽度固定 ~200px，可折叠为纯图标（响应式/用户偏好）。
- 中栏：主操作流，从上到下严格遵循"输入 → 优化(可选) → 参数 → 素材上传(按需) → 生成 → 结果"的视觉顺序，符合创作心智模型。
- 右栏：宽度 ~280px，展示与当前功能类型相关的历史结果（非全部历史，减少信息噪音），可一键"作为输入图"直接回填到中栏的上传区，实现"生成结果无缝进入下一轮创作"。

### 3.3 移动端布局

三栏收为单栏堆叠：顶部功能 Tab（横向可滑动的胶囊组）→ 提示词与参数（可折叠面板，默认收起仅露关键项，"更多参数"展开）→ 生成按钮吸底（sticky）→ 结果区 → 历史结果改为底部横向滚动条而非独立栏。任务中心/画廊改为通过顶部导航的汉堡菜单进入。

## 4. 关键页面详细设计

### 4.1 首页 / Landing
- Hero 区：渐变光晕背景 + 产品标语 + 实时轮播/网格展示示例生成图（占位图，实现时可用官方示例或用户生成结果的匿名展示），主 CTA「开始创作」。
- 三个能力卡片：文生图/图生图/多图合成一组，视频生成一张大卡，提示词优化作为贯穿说明而非单独卡片。
- 底部简要说明"BYOK 模式"：一句话解释需要自备 Agnes API Key、数据仅存本地，附「获取 API Key」外链到 Agnes 官网。
- 可选：MVP 阶段也可以直接跳过 Landing，首次访问未配置 Key 时直接进入工作台并以内嵌引导条提示配置 Key，降低开发量——**建议 MVP 先做这种"轻引导"版本，Landing 页作为二期补充**。

### 4.2 创作工作台 — 文生图
- 提示词多行输入框（占位符给出示例："一只橘猫坐在雨后的窗台上，柔和的晨光，电影感"）。
- 输入框右下角「✨ 优化提示词」按钮：点击后原地展开一个对比条——左侧原文（只读），右侧 AI 改写结果（可编辑文本域，流式打字呈现），下方「采用」「放弃」两个按钮，采用后替换主输入框内容。
- 参数面板：尺寸档位（1K/2K/3K/4K 分段控件）+ 比例（8 个比例的图标化选择，如 1:1 方形图标、16:9 横向条形图标，直观好认）。
- 生成按钮下方小字实时显示"预计输出 XXXX×XXXX px"，基于所选档位+比例即时计算展示（参照接口文档尺寸对照表）。
- 结果区：生成完成后大图淡入展示，悬浮工具条（下载/收藏/复制提示词/以此图继续图生图/放大查看）。

### 4.3 创作工作台 — 图生图
- 在文生图基础上，参数面板上方增加「上传参考图」区域：拖拽/点击/粘贴三种上传方式，上传后显示缩略图 + 删除按钮 + 图片尺寸信息。
- 提供"编辑意图"快捷标签（点击填入提示词片段）：更换背景 / 改变风格 / 调整光线 / 添加元素 / 移除元素，降低不熟悉提示词写法的用户门槛。
- 也支持从右栏历史结果里一键"作为输入图"直接填入上传区（见 3.2）。

### 4.4 创作工作台 — 多图合成
- 上传区支持多选（最多引导 3 张，超过给黄色 `warning` 提示条"第4张起可能产生额外费用"而不强制拦截）。
- 已上传图片以可拖拽排序的横向卡片列表展示，卡片左上角显示序号徽章（对应提示词里的 `<Picture N>` 引用），提示词输入框旁给出"如何引用图片序号"的小提示气泡。
- 预设合成模板标签：角色融合 / 场景合成 / 风格迁移拼贴。

### 4.5 创作工作台 — 视频生成
- 顶部三个子模式切换（胶囊）：文生视频 / 首尾帧控制 / 图片参考。
- **文生视频**：提示词 + 时长滑块（4–12秒）+ 比例选择（对应像素表实时展示）。
- **首尾帧控制**：两个并排的上传槽位（首帧/尾帧），中间用一个箭头连接线暗示"过渡"关系；提示词描述过渡动作。
- **图片参考**：多图上传（最多 5 张，超过禁用继续上传并提示上限），提示词里引用 `<Picture N>`（与多图合成一致的排序交互复用同一组件）。
- 生成后不同于图片的同步等待，视频进入**任务中心**：点击生成后中栏出现一张"任务卡片"（进度条+状态文案），同时右上角任务中心图标出现数字角标；用户可离开去做别的创作，任务在后台轮询，完成后角标高亮 + 桌面内通知条，点击卡片查看/播放/下载视频。

### 4.6 任务中心
- 列表形式，每行：缩略首帧（或占位图标）+ 提示词摘要 + 模式标签 + 状态徽章 + 耗时/创建时间 + 操作（查看/下载/重试/删除）。
- 失败任务展开显示错误 `detail` 原文 + 归类后的中文解释（如"参数超限：参考图数量不能超过5张"），并提供"复制参数去修正"直接跳回工作台并预填参数。

### 4.7 历史画廊
- 瀑布流/网格卡片，顶部筛选：全部/图片/视频 + 收藏 + 按功能类型（文生图/图生图/多图合成/视频）。
- 卡片 hover 显示操作条：复用参数（跳回工作台并预填全部参数，包括原始输入图）、下载、收藏切换、删除。
- 支持"导出全部历史（JSON）"、"导入历史"、"清空历史"（清空需二次确认弹窗，属于不可逆操作）。

### 4.8 设置中心
- Key 配置卡片：输入框（默认掩码显示，右侧眼睛图标切换可见）、Base URL（默认值+可编辑）、「测试连接」按钮（调用一次轻量文本请求验证，成功/失败即时反馈）。
- 显著的隐私说明卡片："你的密钥仅加密保存在本设备浏览器中，本站不会以任何形式上传或留存"，配合小锁图标强化信任感。
- 默认参数配置：默认尺寸/比例/视频时长、默认是否开启提示词优化、Thinking 模式开关、语言（预留）。
- 数据管理区：导出/导入/清空本地数据（历史+设置），清空前二次确认。

## 5. 交互与动效细则

- **生成中状态**：主按钮内文字替换为环形 spinner + "生成中…"，中栏结果区出现带呼吸光效的骨架卡片（渐变边框缓慢流动，暗示"AI 正在工作"但不喧宾夺主）。
- **流式文本**：打字机效果，光标闪烁，用户可点击"停止"提前中断流。
- **拖拽上传**：拖拽经过上传区时边框高亮为 `accent-violet` 虚线并放大 2%，松开后有短暂的缩放回弹动画确认接收。
- **图片放大预览**：点击缩略图以 Modal 形式居中放大，支持左右箭头切换同批次结果，支持滚轮缩放。
- **页面切换**：轻量的淡入+8px位移过渡（150–200ms），避免生硬跳变，但不做夸张的路由动画影响效率。
- **可访问性动效降级**：遵循 `prefers-reduced-motion`，用户系统开启"减少动态效果"时关闭光效/位移动画，仅保留状态色变化。

## 6. 技术架构

### 6.1 总体架构

```
┌──────────────────────────────────────────────────────────────┐
│  浏览器（前端 SPA：React + Vite + TS + Tailwind）                  │
│  - localStorage：API Key（加密存储）、功能配置项                     │
│  - IndexedDB：历史画廊（图片/视频结果元数据 + 缩略图/参数）              │
└───────────────┬──────────────────────────────────────────────┘
                │ fetch（携带用户 Key，经由同域 Function 转发）
                ▼
┌──────────────────────────────────────────────────────────────┐
│  Edge/Serverless Function（无状态代理，与前端同仓库同部署）              │
│  - Cloudflare Pages Functions ｜ Vercel Edge Functions ｜ Netlify Functions │
│  - 职责：透传请求到 Agnes API，转发 Authorization 头，              │
│          流式响应原样转发（文本 SSE / 视频轮询直通），                │
│          仅做参数前置校验与错误包装，不做任何持久化/日志留存用户内容        │
└───────────────┬──────────────────────────────────────────────┘
                │ HTTPS
                ▼
┌──────────────────────────────────────────────────────────────┐
│                     Agnes AI API (api.agnes-ai.cn)              │
│      文本 agnes-2.5-flash │ 图像 agnes-image-2.1-flash │ 视频     │
└──────────────────────────────────────────────────────────────┘
```

**为什么要这一层代理，而不是纯前端直连？**
1. Agnes API 是否对浏览器开放 CORS 目前未在官方文档中确认（见《需求文档》风险项 1），代理层作为保险方案，规避潜在的跨域阻断。
2. 统一在代理层做《API接口文档》第 3.3 节列出的"前置校验"（如视频 size 必须 720P、参考图不超过5张），提前拦截无效请求，节省用户等待和潜在的失败调用。
3. 统一错误结构包装，前端只需处理一种错误格式，不用分别适配三个模型接口的差异。

**代理层的"无状态"红线**：不写日志到任何持久存储、不缓存请求体/响应体、不做用户识别，纯粹是一次性透传+校验，确保"无管理后台、不留存用户数据"的产品承诺在架构层面可验证。

**降级方案**：若联调确认 Agnes API 对浏览器 CORS 完全开放，可将代理层降级为"可选增强"——默认纯前端直连，代理层仅在用户需要（如更稳定的流式转发）时启用，这样项目甚至可以退化为纯静态站点部署到任意静态托管。此决策点在开发阶段第一步就应验证并记录结论。

### 6.2 三大平台的 Function 落地方式

| 平台 | Function 目录约定 | 说明 |
|---|---|---|
| Cloudflare Pages | `/functions/api/[[path]].ts` | Pages Functions，基于 Web标准 Request/Response，天然支持流式 |
| Vercel | `/api/[...path].ts`（Edge Runtime） | 需声明 `export const config = { runtime: 'edge' }` 以支持流式转发 |
| Netlify | `/netlify/edge-functions/proxy.ts` | Netlify Edge Functions，同样基于 Deno/Web 标准 |

三份代码逻辑一致（同一套请求透传+校验逻辑），仅入口文件按各平台约定分别放置；建议将核心转发逻辑抽成共享模块（如 `src/server/proxy-core.ts`），三个入口文件仅做适配层调用，避免逻辑三处漂移。

### 6.3 目录结构建议

```
├── functions/                  # Cloudflare Pages Functions 入口
│   └── api/[[path]].ts
├── api/                        # Vercel Edge Functions 入口
│   └── [...path].ts
├── netlify/edge-functions/     # Netlify Edge Functions 入口
│   └── proxy.ts
├── src/
│   ├── server/
│   │   └── proxy-core.ts       # 三平台共享的转发/校验逻辑
│   ├── pages/                  # 工作台/画廊/任务中心/设置/首页
│   ├── components/             # 按钮/卡片/上传区/参数面板等通用组件
│   ├── features/
│   │   ├── text-to-image/
│   │   ├── image-to-image/
│   │   ├── multi-image/
│   │   ├── video-generation/
│   │   └── prompt-enhancer/
│   ├── lib/
```

### 6.4 状态管理与数据流要点
- 全局状态（轻量，建议 Zustand 或 Context）管理：Key 配置状态、当前生成中任务列表（跨页面可见，用于任务中心角标）。
- 历史画廊数据走 IndexedDB，读写封装为异步 hook，避免大量 Base64/图片元数据塞进 localStorage 导致容量超限（localStorage 仅存轻量配置和加密后的 Key）。
- 视频任务轮询用独立的后台 polling manager（非 React 组件生命周期绑定），保证用户切换页面/关闭当前面板时任务仍在跟踪，并处理 `visibilitychange` 降频。

## 7. 可访问性（a11y）checklist

- 所有交互控件可键盘 Tab 到达并有可见 focus ring（`accent-violet` 描边）。
- 图标按钮均带 `aria-label`；上传区兼容键盘触发文件选择。
- 色彩对比度：正文文字与背景对比度 ≥ 4.5:1（`--text-primary` on `--bg-base`/`--bg-surface` 均需实测达标）。
- 状态类信息（成功/失败/进行中）不仅靠颜色区分，同时配图标+文字。
- 遵循 `prefers-reduced-motion`（见第5节）。
